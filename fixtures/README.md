# Fixtures — **synthetic, not real data**

> **Everything in this directory is synthetic — replace with real downloads.**
> It was generated by `scripts/fixtures/gen_static.py` and `scripts/fixtures/gen_realtime.py`
> because the machine this project was built on could not reach transit APIs. The files are in
> the **real wire formats** (GTFS CSV, GTFS-realtime protobuf with the MTA extensions), so the
> loaders, decoders and the position engine are exercised exactly as they would be in
> production — but the *contents* are invented and must never be presented as accurate.

## What is invented

| Thing | Status |
|---|---|
| Station names | Real names of real stations |
| Station coordinates | **Hand-entered and approximate** (typically within ~100 m, sometimes worse) |
| Stop ids | Follow the public MTA naming scheme for the subway (`L08`, `127N`); LIRR ids are invented |
| Line colours | The MTA's published colours |
| Timetables | **Entirely invented** — constant headways, a flat speed model, a fixed dwell |
| Trip ids | NYCT-style format (`048000_L..N01R`) with invented origin times; LIRR trip ids are clearly marked `SYN26LIRR_…` |
| Track geometry | **Straight lines between stations.** Real subway track curves; these do not |
| Delays | Pseudo-random, deterministic per trip id |
| GPS positions (LIRR) | Computed from the synthetic schedule, not reported by real trains |

## Layout

```
fixtures/
├── gtfs/
│   ├── subway/     static GTFS for the 1 (South Ferry–96 St subset), the 7 and the L
│   └── lirr/       static GTFS for one LIRR branch (Penn–Babylon), two stopping patterns
└── realtime/
    ├── subway-1234567/   recorded GTFS-rt for the 1 and 7      (NYCT extensions)
    ├── subway-l/         recorded GTFS-rt for the L            (NYCT extensions)
    └── lirr/             recorded GTFS-rt for the LIRR branch  (railroad extension, GPS)
```

Each recording directory holds one protobuf `FeedMessage` per 30 s of a one-hour recording
(07:30–08:30 America/New_York on 2026-10-01), plus:

- `index.csv` — `offset_seconds,file,header_timestamp`
- `manifest.properties` — `recorded_start_epoch`, `loop_seconds`, `synthetic=true`

`ReplayFeedAdapter` plays them on a loop at real-time speed and reports a clock offset so the
engine can reason in feed time while the UI shows wall-clock times (ADR 4).

## Deliberately messy data

Real feeds misbehave, so these recordings do too. The stale rules, de-duplication and trip
matching are tested against them:

| Scenario | Where |
|---|---|
| Feed freezes (identical payload, old header timestamp) | `subway-l`, snapshots 40–44 |
| A trip vanishes mid-route | `subway-1234567`, a southbound 7 from snapshot 50 |
| Predictions jump ~2 min backwards | `subway-1234567`, a northbound 1, snapshots 30–31 |
| The same trip appears twice (one stale copy) | `subway-1234567`, a northbound 7, snapshots 80–85 |
| Trips not yet assigned to a train (`is_assigned=false`) | every subway recording, before a trip's origin time |

## Regenerating

```bash
python3 -m pip install protobuf
python3 scripts/fixtures/gen_static.py       # writes fixtures/gtfs/*
python3 scripts/fixtures/gen_realtime.py     # writes fixtures/realtime/*
python3 scripts/fixtures/gen_static.py --check   # CI: fails if the committed files drifted
```

Output is deterministic, so regenerating produces byte-identical files.

## Replacing with real data

`scripts/fetch_real_data.sh` downloads the real static GTFS and records the real realtime feeds
into the same layout. After that:

```bash
./scripts/fetch_real_data.sh                 # writes fixtures-real/
TRACKNYC_FIXTURES_DIR=fixtures-real docker compose -f infra/docker-compose.yml up
```

Or skip replay entirely and poll the live feeds with `TRACKNYC_MODE=live`.

The proto definitions the generator compiles live in `scripts/fixtures/proto/`:
`gtfs-realtime.proto` is Google's published file; `nyct-subway.proto` and `mta-railroad.proto`
were re-typed from the MTA's documentation and should be checked against the current published
versions before you rely on them (the Java decoder reads the extensions by field number from the
unknown-field set, so a changed definition shows up as a failing test, not a silent mis-parse).
